# Feature Specification: 筛选器维度优化

**Feature Branch**: `006-filter-dimensions`
**Created**: 2026-05-06
**Status**: Draft
**Input**: User description: "筛选器的合理性还需要继续优化：1. 日期的筛选：拍摄日期、备份日期等 2. 镜头/拍摄设备信息的筛选：这对摄影爱好者很重要 3. 其他维度，用不同用户角色的视角看所需要的维度，例如地理位置等"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按拍摄日期筛选照片 (Priority: P1)

摄影爱好者拍了大量照片，想回顾去年夏天旅行时的作品。她打开媒体库，选择"拍摄日期"过滤器，设定起止日期为 2025-06-01 至 2025-08-31，立即看到该时段内拍摄的所有照片，而非导入时间在该时段的照片。

**Why this priority**: 拍摄日期是摄影爱好者最核心的筛选维度。当前系统只按导入日期筛选，语义偏差严重——用户以"什么时候拍的"思考，系统却回答"什么时候导入的"，这是最高优先级需修复的体验缺陷。

**Independent Test**: 可通过设置拍摄日期范围并验证结果中的 EXIF date_time_original 均落在范围内来独立测试，无需依赖其他新筛选维度。

**Acceptance Scenarios**:

1. **Given** 资产库中有不同拍摄日期的照片，**When** 用户选择"按拍摄日期"并设定日期范围，**Then** 仅展示 date_time_original 在该范围内的资产
2. **Given** 资产库中某些照片无 EXIF 拍摄日期信息，**When** 用户按拍摄日期筛选，**Then** 无拍摄日期的资产被排除，并显示提示"部分资产因缺少拍摄日期信息未被展示"
3. **Given** 用户同时设置了"拍摄日期"和"导入日期"两个日期范围，**When** 应用筛选，**Then** 两个条件取交集（AND 逻辑）

---

### User Story 2 - 按镜头和拍摄参数筛选 (Priority: P1)

摄影爱好者想找出所有用 56mm f/1.2 镜头拍摄的人像，或所有长曝光（慢快门）的风光照片。他打开筛选器，从镜头列表中选择"XF56mmF1.2 R WR"，或设定快门速度小于 1/30 秒，快速定位到目标照片。

**Why this priority**: 镜头和拍摄参数是摄影爱好者区分作品的核心维度，直接影响拍摄风格的回顾与选择。数据库中已有完整 EXIF 数据但未暴露为筛选条件，属于高价值低成本改进。

**Independent Test**: 可通过选择特定镜头或设置快门速度范围，验证返回资产的 EXIF 数据匹配筛选条件来独立测试。

**Acceptance Scenarios**:

1. **Given** 资产库中有多支镜头拍摄的照片，**When** 用户从镜头列表中选择特定镜头，**Then** 仅展示使用该镜头拍摄的照片
2. **Given** 用户设定光圈范围 f/1.2 - f/2.8，**When** 应用筛选，**Then** 仅展示 f_number 在该范围内的照片
3. **Given** 用户设定焦距范围 50mm - 200mm，**When** 应用筛选，**Then** 仅展示 focal_length 在该范围内的照片
4. **Given** 用户设定快门速度慢于 1/30 秒，**When** 应用筛选，**Then** 仅展示 exposure_time ≥ 1/30 的照片
5. **Given** 资产库中某些照片无 EXIF 拍摄参数，**When** 用户按参数筛选，**Then** 无相关参数的资产被排除

---

### User Story 3 - 按地理位置筛选 (Priority: P2)

旅行摄影爱好者想回顾东京旅行时的照片。她打开筛选器，在地点输入框中输入"Tokyo"，系统返回 GPS 坐标位于东京附近的所有照片。

**Why this priority**: 地理位置筛选对旅行摄影爱好者价值极高，但需要额外的地理编码（reverse geocoding）基础设施支持，复杂度高于前两个故事，因此优先级略低。

**Independent Test**: 可通过输入城市名或设定经纬度范围，验证返回资产的 GPS 坐标落在目标区域内来独立测试。

**Acceptance Scenarios**:

1. **Given** 资产库中有含 GPS 信息的照片，**When** 用户输入城市或地点名称，**Then** 系统返回 GPS 坐标匹配该地点范围的照片
2. **Given** 资产库中大部分照片无 GPS 信息，**When** 用户按地理位置筛选，**Then** 无 GPS 的资产被排除，筛选结果旁显示"仅展示含位置信息的资产"
3. **Given** 资产库中无任何照片含 GPS 信息，**When** 用户打开地理位置筛选器，**Then** 显示"暂无含位置信息的资产"空状态提示

---

### User Story 4 - 按视频属性筛选 (Priority: P2)

视频创作者想找出所有 HDR 视频素材用于调色参考，或找出所有 4K 分辨率的素材用于导出。他打开筛选器，勾选"HDR"，或选择视频编码格式，快速定位目标视频。

**Why this priority**: 视频属性筛选对视频创作者有价值，但 Lenbrary 当前以照片管理为主，视频资产占比相对较低，优先级略低于摄影相关维度。

**Independent Test**: 可通过勾选 HDR 或选择编码格式，验证返回视频资产的元数据匹配筛选条件来独立测试。

**Acceptance Scenarios**:

1. **Given** 资产库中有 HDR 和 SDR 视频，**When** 用户勾选"仅 HDR"，**Then** 仅展示 is_hdr=true 的视频
2. **Given** 资产库中有不同编码的视频，**When** 用户选择特定视频编码（如 H.265），**Then** 仅展示该编码的视频
3. **Given** 用户已筛选 type=video 并进一步选择帧率范围，**When** 应用筛选，**Then** 仅展示 frame_rate 在范围内的视频
4. **Given** 用户设置了视频时长范围（如 30s - 5min），**When** 应用筛选，**Then** 仅展示 duration 在范围内的视频

---

### User Story 5 - 筛选器交互优化 (Priority: P3)

摄影爱好者在筛选器面板中同时使用多个维度组合筛选，系统应提供清晰的筛选状态反馈、合理的默认值、以及快速重置能力。相机筛选应从自由文本输入升级为带自动补全的选择器。

**Why this priority**: 交互优化提升整体使用效率，但核心筛选维度的可用性是先决条件，因此排在功能维度之后。

**Independent Test**: 可通过同时激活多个筛选器并验证状态指示、重置功能来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户激活了 5 个筛选条件，**When** 查看筛选器面板，**Then** 顶部显示"5 个筛选条件已激活"，并提供一键清除按钮
2. **Given** 相机筛选器当前是自由文本输入，**When** 用户点击相机筛选器，**Then** 显示库中已有相机型号的自动补全列表
3. **Given** 用户对数值型筛选器（光圈、焦距等）设定了范围，**When** 查看激活的筛选条件标签，**Then** 显示可读的范围描述（如"f/1.2 - f/2.8"）

---

### Edge Cases

- 当资产缺少 EXIF 拍摄日期时，拍摄日期筛选是否应提供"未知日期"选项以包含这些资产？
- 当 GPS 坐标解析的城市名与用户输入不完全匹配时（如"东京"vs"Tokyo"），如何处理多语言地点搜索？
- 光圈值在 EXIF 中存储为浮点数（如 2.8），筛选时如何处理精度问题（f/2.8 vs f/2.7999）？
- 快门速度存储为分数形式的浮点数（如 0.033333 表示 1/30s），筛选 UI 如何让用户以直觉的分数形式操作？
- 同时应用拍摄日期 + 导入日期 + 镜头 + 地理位置 + HDR 等多维度组合时，性能是否可接受？
- 视频专属筛选器（HDR、编码、帧率）在照片视图中是否应隐藏？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持按拍摄日期（EXIF date_time_original）筛选资产，支持起止日期范围
- **FR-002**: 系统必须支持按导入日期（created_at）筛选资产，与拍摄日期独立，两者可同时使用
- **FR-003**: 系统必须在日期筛选 UI 中明确区分"拍摄日期"和"导入日期"两个维度，避免语义混淆
- **FR-004**: 系统必须支持按镜头型号（lens_model）筛选照片，提供库中已有镜头的自动补全列表
- **FR-005**: 系统必须支持按光圈范围（f_number）筛选照片
- **FR-006**: 系统必须支持按焦距范围（focal_length）筛选照片
- **FR-007**: 系统必须支持按快门速度范围（exposure_time）筛选照片
- **FR-008**: 系统必须支持按 ISO 范围筛选照片
- **FR-009**: 系统必须支持按地理位置（GPS 坐标）筛选资产，用户可通过输入地点名称来搜索
- **FR-010**: 系统必须在资产无 GPS 数据时提供明确的空状态提示
- **FR-011**: 系统必须支持按 HDR 状态筛选视频资产
- **FR-012**: 系统必须支持按视频编码格式（video_codec）筛选视频资产
- **FR-013**: 系统必须支持按视频时长范围（duration）筛选视频资产
- **FR-014**: 系统必须支持按视频帧率范围（frame_rate）筛选视频资产
- **FR-015**: 相机筛选器必须从自由文本输入升级为带自动补全的选择器，基于库中已有相机的 make/model
- **FR-016**: 系统必须在筛选器面板中展示当前激活的筛选条件数量和一键清除功能
- **FR-017**: 数值型筛选器（光圈、焦距、快门速度、ISO、帧率、时长）必须以用户友好的方式展示范围值（如快门速度显示为分数形式，光圈显示为 f/x 格式）
- **FR-018**: 视频专属筛选器（HDR、编码、帧率、时长）在用户已筛选 type=image 时应自动隐藏
- **FR-019**: 系统必须在资产缺少筛选所需元数据时提供提示，而非静默排除

### Key Entities

- **拍摄日期 (CaptureDate)**: EXIF date_time_original 字段，表示照片实际拍摄的时间，与导入时间独立
- **导入日期 (ImportDate)**: 资产 created_at 字段，表示资产被导入媒体库的时间
- **镜头 (Lens)**: EXIF lens_model 字段，标识拍摄所用镜头，如"XF56mmF1.2 R WR"
- **拍摄参数 (ExposureParams)**: 包含 f_number（光圈）、focal_length（焦距）、exposure_time（快门速度）、iso（感光度）等 EXIF 字段的组合
- **地理位置 (Location)**: EXIF gps_latitude/gps_longitude 字段，可通过反向地理编码映射到地点名称
- **视频属性 (VideoAttributes)**: 包含 is_hdr、video_codec、duration、frame_rate 等视频元数据字段

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 10 秒内完成任意单一筛选维度的设置并看到筛选结果
- **SC-002**: 5 个维度组合筛选时，结果返回时间不超过 2 秒
- **SC-003**: 拍摄日期筛选的结果 100% 准确匹配 EXIF date_time_original 范围，无导入日期混淆
- **SC-004**: 镜头自动补全列表覆盖库中 100% 已存在的镜头型号，无遗漏
- **SC-005**: 地理位置搜索支持至少城市级别的地点名称匹配
- **SC-006**: 新增筛选维度后，已有筛选功能（type、favorite、tag、hasThumbnail 等）行为不变，零回归
- **SC-007**: 无相关元数据的资产在筛选时获得明确提示，而非被静默排除

## Assumptions

- 反向地理编码（GPS 坐标 → 地点名称）优先使用离线方案或预计算，避免对实时外部 API 的依赖
- 快门速度在筛选 UI 中以直观方式展示（如"慢于 1/30s"），但底层仍以浮点数存储和比较
- 地理位置筛选第一版仅支持文本输入城市/地点名称搜索，不包含地图交互
- 视频属性筛选器仅在 type=video 或未限定类型时可见，type=image 时自动隐藏
- ISO、光圈等数值型筛选器使用滑块或范围输入，具体交互在计划阶段确定
- 缺少 EXIF 拍摄日期的资产在"拍摄日期"筛选中默认被排除，但提供"无拍摄日期"选项让用户选择是否包含
- 相机筛选器的自动补全列表从数据库中已存在的 make + model 组合动态生成
